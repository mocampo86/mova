# US-082 — Support overnight court availability rules

## Status

Ready

## Objective

As a complex administrator, I want to configure court availability rules that span midnight (e.g., 22:00–02:00) so that overnight courts can be booked correctly.

## Functional description

Currently, `CourtAvailabilityRule.FitsSlotDuration()` and the `AvailabilitySlotGenerator` already support ranges where the end time is on the next calendar day, and the React `EditCourtPage` accepts such ranges. However, `UpdateCourtAvailabilityRulesCommandValidator` requires `EndTime > StartTime`, and the database has a `StartTime < EndTime` check constraint. This prevents saving overnight availability rules. This user story enables end-to-end support for overnight rules.

## Acceptance criteria

- [ ] An administrator can save a court availability rule where `StartTime` is later than `EndTime` (e.g., 22:00–02:00).
- [ ] The validator correctly checks that the duration, including the wrap-around past midnight, is evenly divisible by `SlotDurationMinutes`.
- [ ] The database check constraint is updated to allow overnight ranges while still rejecting zero-duration rules.
- [ ] The public availability endpoint returns slots that wrap past midnight when an overnight rule and matching business hours are configured.
- [ ] The frontend edit form continues to accept and display overnight ranges correctly.
- [ ] Unit and integration tests cover overnight rule creation and slot generation.
- [ ] An EF Core migration is created for the database constraint change.

## Business rules

1. A court availability rule may span across midnight.
2. `StartTime` and `EndTime` must not be equal.
3. The total duration, including any wrap-around, must be evenly divisible by the slot duration.
4. The generated slots must respect the complex's `BusinessHours` for that day, which may also be overnight.
5. Only one rule per day of week per court (enforced by BUGFIX-003).

## Validations

- Validate the court exists and belongs to the requested complex.
- Validate `StartTime != EndTime`.
- Validate `SlotDurationMinutes > 0`.
- Validate the wrap-around duration is evenly divisible by `SlotDurationMinutes`.
- Validate `DayOfWeek` is in `0–6`.

## Error cases

| Scenario | Expected behavior |
|---|---|
| `StartTime == EndTime` | `400 Bad Request` with zero-duration error. |
| Duration not divisible by slot duration | `400 Bad Request` with slot-duration error. |
| Overnight range with valid parameters | `200 OK` with persisted rule. |
| `DayOfWeek` outside `0–6` | `400 Bad Request` with validation error. |

## Security considerations

- Only authorized complex administrators may update availability rules.
- Do not reveal internal court or rule identifiers in error responses.
- Keep the existing `ComplexAdmin` authorization policy unchanged.

## Technical notes

- API: `PUT /api/v1/complexes/{complexId}/courts/{courtId}/availability` remains the same; only validation and constraints change.
- The `CourtAvailabilityRule` domain already supports overnight in `FitsSlotDuration`; align the validator and database with it.
- Change the `chk_court_availability_time` constraint from `"StartTime" < "EndTime"` to `"StartTime" <> "EndTime"` (or remove it and rely on validator/domain).
- Ensure `AvailabilitySlotGenerator` continues to handle overnight rules and business hours correctly.
- Consider whether `BusinessHours` should also support overnight hours; if not, document that overnight availability also requires overnight business hours.

## Tests required

### Unit

- `CourtAvailabilityRule.Create` with an overnight range succeeds when duration is divisible.
- `CourtAvailabilityRule.Create` with an overnight range fails when duration is not divisible.
- `UpdateCourtAvailabilityRulesCommandValidator` accepts overnight ranges.
- `AvailabilitySlotGenerator` produces slots across midnight for an overnight rule.

### Integration

- `PUT .../availability` accepts an overnight rule.
- The public availability endpoint returns overnight slots when both rule and business hours are overnight.
- The admin availability endpoint returns the saved overnight rule unchanged.

### Frontend

- `EditCourtPage` submits an overnight rule successfully.
- `EditCourtPage` displays overnight slots correctly (if a preview is added).

## Out of scope

- Bulk editing of availability rules.
- Visual preview of generated slots in the admin UI.
- Notifications for rule changes.

- US-021 — Set the duration of each booking slot per court.
- BUGFIX-003 — Enforce one availability rule per court and day of week (to avoid duplicate rules).
