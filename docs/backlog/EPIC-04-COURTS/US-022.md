# US-022 — Activate or deactivate a court

## Status

Ready

## Objective

As an administrator, I want to activate or deactivate a court.

## Functional description

This user story enables the administrator to activate or deactivate a court. It belongs to EPIC-04 — Court Administration.

## Acceptance criteria

- [ ] Activate or deactivate a court is implemented and available to the administrator.
- [ ] The resource status can be toggled between active and inactive.
- [ ] Inactive resources are excluded from public listings.
- [ ] Only authorized administrators can change the status.
- [ ] A court must have at least one active sport before it can accept reservations.

## Business rules

- CRUD for `Court`.
- Association of one or more `Sport` to a court.
- `CourtAvailabilityRule` per day of week.
- `BusinessHours` per complex.
- Activation/deactivation of courts.
- Preparation for court-level time blocks.
- Only authorized users can modify resources they own or administer.

## Validations

- Validate required fields and data types server-side.
- Return clear, structured error messages for invalid input.

## Error cases

- Invalid or missing input data.
- User is not authenticated or authorized.
- The referenced resource does not exist.

## Security considerations

- Authenticate and authorize every mutating request.
- Do not expose internal implementation details in error responses.
- Avoid logging sensitive data such as passwords, tokens, or PII.

## Technical notes

- `Court`: `Id`, `SportsComplexId`, `Name`, `Description`, `SurfaceType`, `Indoor`, `Status`, `CreatedAt`, `UpdatedAt`.
- `CourtSport` many-to-many join table.
- `CourtAvailabilityRule`: `CourtId`, `DayOfWeek`, `StartTime`, `EndTime`, `SlotDurationMinutes`, `IsActive`.
- Validate `StartTime < EndTime` and that slots fit within the range.
