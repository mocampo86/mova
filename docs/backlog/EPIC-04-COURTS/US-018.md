# US-018 — Create a court with name, description, surface, and indoor/outdoor flag

## Objective

As an administrator, I want to create a court with name, description, surface, and indoor/outdoor flag.

## Functional description

This user story enables the administrator to create a court with name, description, surface, and indoor/outdoor flag. It belongs to EPIC-04 — Court Administration.

## Acceptance criteria

- [ ] Create a court with name, description, surface, and indoor/outdoor flag is implemented and available to the administrator.
- [ ] Required fields are validated before persistence.
- [ ] The created resource is persisted and returned with an identifier.
- [ ] Only authenticated and authorized users can create the resource.
- [ ] Timestamps `CreatedAt` and `UpdatedAt` are tracked.
- [ ] A court must have at least one active sport before it can accept reservations.

## Business rules

- CRUD for `Court`.
- Association of one or more `Sport` to a court.
- `CourtAvailabilityRule` per day of week.
- `BusinessHours` per complex.
- Activation/deactivation of courts.
- Preparation for court-level time blocks.
- Input validation must be enforced on the server, not only the client.
- Only authorized users can modify resources they own or administer.

## Validations

- Validate required fields and data types server-side.
- Enforce length, format, and range limits.
- Check uniqueness where applicable.
- Verify the actor has permission to create or update the resource.
- Validate name is provided and well-formed.
- Validate description is provided and well-formed.
- Validate surface is provided and well-formed.
- Return clear, structured error messages for invalid input.

## Error cases

- Invalid or missing input data.
- User is not authenticated or authorized.
- The referenced resource does not exist.
- Duplicate or conflicting data violates uniqueness rules.

## Security considerations

- Authenticate and authorize every mutating request.
- Do not expose internal implementation details in error responses.
- Avoid logging sensitive data such as passwords, tokens, or PII.
- Sanitize and validate all user input to prevent injection attacks.

## Technical notes

- `Court`: `Id`, `SportsComplexId`, `Name`, `Description`, `SurfaceType`, `Indoor`, `Status`, `CreatedAt`, `UpdatedAt`.
- `CourtSport` many-to-many join table.
- `CourtAvailabilityRule`: `CourtId`, `DayOfWeek`, `StartTime`, `EndTime`, `SlotDurationMinutes`, `IsActive`.
- Validate `StartTime < EndTime` and that slots fit within the range.
