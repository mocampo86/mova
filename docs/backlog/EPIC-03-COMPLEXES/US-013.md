# US-013 — Create a complex with name, description, address, and contact data

## Status

Done

## Objective

As an administrator, I want to create a complex with name, description, address, and contact data.

## Functional description

This user story enables the administrator to create a complex with name, description, address, and contact data. It belongs to EPIC-03 — Sports Complex Administration.

## Acceptance criteria

- [x] Create a complex with name, description, address, and contact data is implemented and available to the administrator.
- [x] Required fields are validated before persistence.
- [x] The created resource is persisted and returned with an identifier.
- [x] Only authenticated and authorized users can create the resource.
- [x] Timestamps `CreatedAt` and `UpdatedAt` are tracked.
- [x] A logged-in user can create a complex and becomes its first administrator.
- [x] Complex data can be edited by an administrator of that complex.

## Business rules

- CRUD for `SportsComplex`.
- Complex activation/deactivation.
- Public information configuration.
- Address and optional coordinates.
- Linking the first administrator to a complex.
- Superadmin moderation (preparation).
- Input validation must be enforced on the server, not only the client.
- Only authorized users can modify resources they own or administer.

## Validations

- Validate required fields and data types server-side.
- Enforce length, format, and range limits.
- Check uniqueness where applicable.
- Verify the actor has permission to create or update the resource.
- Validate name is provided and well-formed.
- Validate description is provided and well-formed.
- Validate address is provided and well-formed.
- Validate contact is provided and well-formed.
- Return clear, structured error messages for invalid input.

## Error cases

- Invalid or missing input data.
- User is not authenticated or authorized.
- The referenced resource does not exist.
- Duplicate or conflicting data violates uniqueness rules.

## Security considerations

- Authenticate and authorize every mutating request.
- Do not expose internal implementation details in error responses.
- Avoid logging sensitive data such as passwords, tokens, or PII.
- Sanitize and validate all user input to prevent injection attacks.
- Verify the actor belongs to or administers the affected complex.

## Technical notes

- `SportsComplex` entity: `Id`, `Name`, `Description`, `Address`, `City`, `Latitude`, `Longitude`, `PhoneNumber`, `Email`, `Status`, `CreatedAt`, `UpdatedAt`.
- `ComplexAdministrator` links user and complex with a role.
- Public listing returns only active complexes and public fields.
