# US-072 — User dashboard overview

## Status

Ready

## Objective

As a user, I want a dashboard home page so I can access all my features and reservations at a glance.

## Functional description

This user story creates a centralized dashboard for authenticated end users. The dashboard replaces the current `/user` placeholder and aggregates all existing user-facing functionality so that the user can see their reservations, discover complexes, manage their profile, and review account status without navigating through disconnected pages. It belongs to EPIC-13 — User Dashboard.

## Acceptance criteria

- [ ] User dashboard is implemented and available at `/user`.
- [ ] The dashboard shows a welcome header with the user's name/email.
- [ ] The dashboard displays a summary of upcoming reservations (next N items) with a link to the full reservation list.
- [ ] The dashboard displays a summary of reservation history with a link to the full history.
- [ ] The dashboard provides an entry point to search and browse active complexes (existing US-024/US-025 flow).
- [ ] The dashboard provides an entry point to create a new single or recurring reservation (US-029/US-037).
- [ ] The dashboard displays any active block notifications for the current user per complex (US-047).
- [ ] The dashboard provides an entry point to view and update the user profile (US-009).
- [ ] The dashboard displays the current language selector or respects the persisted language (US-061).
- [ ] All existing user-facing pages (`/complexes`, `/complexes/:complexId`, reservation flows, profile) are reachable from the dashboard navigation or summary cards.
- [ ] Incomplete profiles are redirected to `/complete-profile` before accessing the dashboard.
- [ ] Unauthorized or unauthenticated users are redirected to `/login` or `/unauthorized`.
- [ ] The layout is responsive and supports mobile, tablet, and desktop.
- [ ] Dashboard labels and empty states are translated into the active language.

## Business rules

- A user can only see their own reservations, profile, and block status.
- Block status is shown per complex; being blocked in one complex does not affect others.
- Only active complexes and courts are presented for discovery.
- Upcoming and historical reservations are sorted by start time.
- All date/time values are stored in UTC and converted to local time in the frontend.
- The dashboard must respect the user's language preference.

## Validations

- Validate the user is authenticated and holds a `User`, `ComplexAdmin`, or `SuperAdmin` role.
- Validate profile completeness before rendering the dashboard; redirect if phone number is missing.
- Validate query parameters and pagination inputs for list endpoints.
- Return clear, structured error messages for invalid input or unauthorized access.

## Error cases

- User is not authenticated or authorized.
- User profile is incomplete.
- The requested data does not exist or is not accessible.
- Network or server errors when loading dashboard summaries.
- No upcoming or historical reservations.

## Security considerations

- Authenticate and authorize every request.
- Do not expose internal implementation details in error responses.
- Avoid logging sensitive data such as tokens or PII.
- Ensure users can only view data they are allowed to access (multi-tenancy).
- Protect dashboard routes with `RequireRole`.

## Technical notes

- Create or extend `UserLayout` in `src/mova-web/src/layouts/`.
- Replace `UserHomePage` with a `UserDashboardPage` at `/user`.
- Add nested routes under `/user` such as `/user/reservations`, `/user/recurring`, `/user/profile` if not already present.
- Reuse `usersApi` for profile, `complexApi` for complex discovery, and `reservationApi` for reservations.
- Add a `useMyReservations` hook consuming `GET /api/v1/users/me/reservations` if not already present in the reservation feature.
- Consider a summary endpoint `GET /api/v1/users/me/dashboard` for aggregated counts.
- Use Material-UI cards, grid, loading skeletons, and empty states.
- Update `src/mova-web/README.md` route table.
- Add translation keys under `src/i18n/locales/`.

## Tests required

- **Unit**: dashboard card rendering, summary formatting, and guard behavior.
- **Integration**: API endpoint behavior for dashboard data aggregation.
- **E2E**: authenticated user views dashboard, navigates to reservations, complex search, and profile.

## Out of scope

- Complex creation or management.
- Payments, deposits, or real-time notifications.
- Google Maps integration, complex main image, favorites, or additional services (these are backlog notes and require separate stories if needed).
- Advanced analytics, charts, or reporting.
