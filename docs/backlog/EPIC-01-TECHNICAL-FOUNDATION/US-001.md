# US-001 — Runnable .NET Solution

## Status

Done

## Objective

As a developer, I want a runnable .NET solution so I can implement API features.

## Functional description

Create the solution file and the initial backend and test projects following the layered architecture defined for the system. Each project must reference only the layers it is allowed to depend on, and the entire solution must compile without errors.

## Acceptance criteria

- [ ] A solution file exists and references all backend and test projects.
- [ ] Backend projects `Api`, `Application`, `Domain`, `Infrastructure`, and `Contracts` are created.
- [ ] Test projects `UnitTests`, `IntegrationTests`, and `ArchitectureTests` are created.
- [ ] Project references respect layer separation:
  - `Domain` has no project references.
  - `Contracts` has no project references.
  - `Application` references `Domain` and `Contracts`.
  - `Infrastructure` references `Domain`, `Application`, and `Contracts`.
  - `Api` references `Application`, `Infrastructure`, and `Contracts`.
- [ ] `dotnet build` succeeds for all projects from the solution root.
- [ ] No build warnings remain (where warnings are treated as errors).

## Business rules

- The domain layer must not depend on infrastructure, data access, or presentation concerns.
- The application layer must not depend on concrete infrastructure implementations.
- Shared contracts must be referenceable by both the API and the application layer.

## Validations

- Run `dotnet build` from the solution root.
- Run `dotnet test` if any architecture tests already verify dependency direction.

## Error cases

- Missing project references cause compile failures.
- Circular dependencies are reported and must be removed.
- Build warnings are treated as errors when configured.

## Security considerations

- No secrets, connection strings, or API keys in project files or `appsettings.json`.
- Keep NuGet package references minimal and pinned to a specific version or allowed range.

## Technical notes

- Backend projects: `Api`, `Application`, `Domain`, `Infrastructure`, `Contracts`.
- Tests projects: `UnitTests`, `IntegrationTests`, `ArchitectureTests`.
- Use the .NET version and C# language version defined in the solution architecture.

## Tests required

- **Unit**: not applicable while scaffolding.
- **Integration**: not applicable while scaffolding.
- **Architecture**: verify dependency direction once the `ArchitectureTests` project exists.

## Out of scope

- Implementing actual API endpoints.
- Database migrations and EF Core setup.
- Authentication and authorization.

## Dependencies

None. This is the first story of the epic.

## Definition of Done

- All acceptance criteria are met.
- `dotnet build` passes for the entire solution.
- Project references follow architecture rules.
- Code review is approved.
