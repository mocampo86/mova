# US-007 — CI Pipeline for Build and Test

## Objective

As a team, I want a CI pipeline that builds and tests the solution on every PR.

## Functional description

Set up a CI pipeline that builds and tests the backend and frontend on every pull request so the team catches regressions before merging.

## Acceptance criteria

- [ ] A CI pipeline definition file is added to the repository.
- [ ] The pipeline triggers on pull requests to the main or develop branch.
- [ ] A backend job restores, builds, and tests the .NET solution (`dotnet build`, `dotnet test`).
- [ ] A frontend job installs dependencies, lints, builds, and tests the React app (`npm ci`, `npm run lint`, `npm run build`, `npm run test`).
- [ ] Backend and frontend jobs run in parallel.
- [ ] The pipeline fails if any build or test step fails.
- [ ] No secrets are exposed in pipeline logs.
- [ ] Third-party actions or tasks are pinned to a version or commit SHA.

## Business rules

- CI must run for every pull request.
- No pull request is merged until the CI pipeline is green.
- CI credentials and secrets must use the minimum privileges required.

## Validations

- Open a test pull request and verify the pipeline runs.
- Introduce a failing test and confirm the pipeline fails.
- Inspect pipeline logs for secrets or sensitive values.

## Error cases

- Backend build fails because of compilation errors.
- Backend tests fail.
- Frontend build, lint, or tests fail.
- The CI environment is missing required SDKs or runtimes.
- Pipeline YAML has a syntax error.

## Security considerations

- Do not commit secrets inside the pipeline YAML.
- Use repository or organization secrets for any required credentials.
- Pin third-party actions to a specific version or SHA to reduce supply-chain risk.

## Technical notes

- GitHub Actions (`/.github/workflows`) or Azure DevOps pipelines (`/azure-pipelines.yml`).
- Use the .NET and Node versions defined in the project.
- Consider path filters so backend jobs run only when backend files change and frontend jobs run only when frontend files change.

## Tests required

- None beyond the pipeline itself, which validates builds and tests.

## Out of scope

- Continuous deployment or release pipelines.
- Running E2E tests in CI (may be added later).

## Dependencies

- US-001 — Runnable .NET Solution.
- US-002 — React Application Scaffold.
- US-003 — PostgreSQL Local Setup with Docker Compose (for integration tests).
- US-006 — Health Checks (for integration test coverage).

## Definition of Done

- CI pipeline runs on pull requests.
- Backend and frontend builds and tests pass.
- Pipeline is documented in the project README or setup docs.
- Code review is approved.

## Project affected

DevOps / CI configuration.
