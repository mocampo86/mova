# US-003 — PostgreSQL Local Setup with Docker Compose

## Status

Done

## Objective

As a developer, I want PostgreSQL running locally via Docker Compose so I can develop and test persistently.

## Functional description

Add a Docker Compose service for PostgreSQL, configure a persistent volume, and set up connection configuration in the backend so the API can connect. Local credentials must be kept out of source control.

## Acceptance criteria

- [x] A `docker-compose.yml` (or `compose.yml`) file defines a PostgreSQL service.
- [x] PostgreSQL version, port, database name, user, and password are configurable via environment variables.
- [x] A named volume or bind mount persists data across container restarts.
- [x] `docker compose up -d` starts the database without errors.
- [x] `docker compose down` stops the container cleanly.
- [x] `appsettings.Development.json` contains a connection string template without secrets.
- [x] The local database password is stored in .NET User Secrets, not in source control.
- [x] The backend can connect to the database at startup.

## Business rules

- Local database credentials must not be committed.
- Data must persist across container restarts.
- The database service must be reachable from the backend and from integration tests.

## Validations

- Run `docker compose up -d` and verify the container is healthy.
- Verify the backend can open a connection using the configured connection string.
- Confirm `.gitignore` excludes `.env` files and `secrets.json`.

## Error cases

- PostgreSQL port is already in use.
- Volume permissions prevent the container from starting.
- Required environment variables are missing.
- Connection string points to an unreachable host or port.

## Security considerations

- Default or local passwords must not be committed.
- Provide an `.env.example` file with placeholder values.
- Do not commit `.env` files.

## Technical notes

- Use PostgreSQL stable version defined in the architecture.
- Docker Compose with a named volume for persistence.
- Connection string should be built from configuration providers.

## Tests required

- **Integration**: a simple database connectivity test verifying the backend can open a connection.

## Out of scope

- Production database provisioning.
- Entity Framework Core migrations and entity configuration (covered later).

## Dependencies

- US-001 — Runnable .NET Solution.

## Definition of Done

- `docker compose up -d` starts PostgreSQL.
- Backend connects successfully.
- No secrets are committed.
- Integration connectivity test passes.

## Project affected

Backend infrastructure and local development environment.

`feature/US-003-postgres-docker`

Add the Docker Compose PostgreSQL service, configure the development connection string and User Secrets, test `docker compose up -d`, and verify backend connectivity. Do not add migrations yet.
