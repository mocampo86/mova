# US-068 — Edit a court from admin panel

## Status

Done

## Objective

As a complex administrator, I want to edit a court from the admin panel so its information stays accurate.

## Functional description

This user story enables the complex administrator to edit an existing court of their sports complex from the admin dashboard. It belongs to EPIC-12 — Complex Admin Dashboard.

## Acceptance criteria

- [x] Edit court form is implemented and available at `/admin/complex/:complexId/courts/:courtId/edit`.
- [x] The existing resource is identified and updated.
- [x] The form pre-populates the current court data.
- [x] Input validation matches the rules used at creation.
- [x] `UpdatedAt` is refreshed after a successful update.
- [x] Only authorized administrators can update the resource.
- [x] After successful update, the administrator is redirected to the court list.

## Business rules

- CRUD for `Court`.
- Association of one or more `Sport` to a court.
- Input validation must be enforced on the server, not only the client.
- Only authorized users can modify resources they own or administer.

## Validations

- Validate required fields and data types server-side.
- Enforce length, format, and range limits.
- Check uniqueness where applicable.
- Verify the actor has permission to update the resource.
- Return clear, structured error messages for invalid input.

## Error cases

- Invalid or missing input data.
- User is not authenticated or authorized.
- The referenced resource does not exist.
- Duplicate or conflicting data violates uniqueness rules.

## Security considerations

- Authenticate and authorize every mutating request.
- Do not expose internal implementation details in error responses.
- Avoid logging sensitive data such as passwords, tokens, or PII.
- Sanitize and validate all user input to prevent injection attacks.
- Verify the actor belongs to or administers the affected complex.

## Technical notes

- If the backend endpoint `PUT /api/v1/complexes/{complexId}/courts/{courtId}` does not exist, it must be added.
- Reuse existing `Court` entity and validation patterns.
- Use `react-hook-form` with `zod` resolver.
- Fetch available sports from `GET /api/v1/sports`.

## Tests required

- **Unit**: domain logic and validation rules.
- **Integration**: API endpoint behavior and persistence.
- **E2E**: admin edits a court from the panel.
