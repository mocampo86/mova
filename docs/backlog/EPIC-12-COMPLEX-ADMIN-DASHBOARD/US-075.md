# US-075 — Configure the cancellation policy from the admin panel

## Status

Ready

## Objective

As a complex administrator, I want to configure my complex's cancellation policy from the admin panel so that I can control whether users may cancel reservations and how far in advance they must do so.

## Functional description

This user story adds a `Configuration` option to the complex admin panel. Initially, the configuration page contains only the cancellation policy for the selected sports complex:

```json
{
  "CancellationPolicy": {
    "MinimumHours": 24,
    "AllowUserCancellation": true
  }
}
```

The settings are scoped to the selected complex and are used by the user reservation cancellation flow.

## Acceptance criteria

- [ ] The complex admin panel shows a `Configuration` navigation option for an authorized administrator.
- [ ] The configuration page is available at `/admin/complex/:complexId/configuration`.
- [ ] The page displays the current `MinimumHours` and `AllowUserCancellation` values for the selected complex.
- [ ] An authorized administrator can update `MinimumHours` and save the changes.
- [ ] An authorized administrator can enable or disable `AllowUserCancellation` and save the changes.
- [ ] Saved settings are persisted and are returned when the configuration page is opened again.
- [ ] `MinimumHours` accepts only whole numbers greater than or equal to zero.
- [ ] Only an active administrator of the selected complex can read or update its configuration.
- [ ] Unauthorized users and administrators of another complex cannot read or update the settings.
- [ ] User cancellation uses the configured values for the reservation's complex.
- [ ] When `AllowUserCancellation` is disabled, user cancellation is rejected with a clear structured error.
- [ ] When `AllowUserCancellation` is enabled, cancellation is allowed only before the configured minimum-hour deadline.
- [ ] The existing default values remain `MinimumHours = 24` and `AllowUserCancellation = true` for complexes without an explicit configuration.
- [ ] The page includes loading, save-success, validation-error, and authorization-error states.
- [ ] The configuration page is responsive and uses the existing application translations.

## Business rules

- Cancellation policy settings are scoped per sports complex.
- `MinimumHours` represents the minimum number of hours before the reservation start at which a user may cancel.
- `AllowUserCancellation = false` disables user self-cancellation for the complex.
- This story changes user cancellation behavior only; administrators may continue to cancel reservations according to the existing administrative rules.
- Configuration changes apply to future cancellation requests and do not alter already-cancelled reservations.

## Validations

- Validate `MinimumHours` server-side as an integer greater than or equal to zero.
- Validate that the complex exists and belongs to the administrator's authorized scope.
- Do not trust the `complexId` or policy values supplied by the client.
- Return structured validation and authorization errors.

## Error cases

- The administrator is not authenticated or is not authorized for the selected complex.
- The selected complex does not exist.
- `MinimumHours` is missing, negative, fractional, or outside the supported range.
- The policy cannot be saved.
- A user attempts to cancel while `AllowUserCancellation` is disabled.
- A user attempts to cancel after the configured deadline.

## Security considerations

- Protect read and update endpoints with complex-scoped administrator authorization.
- Prevent cross-complex reads and updates.
- Do not expose secrets or sensitive user data in the configuration response.
- Do not log tokens or personal data.
- Record the administrator actor and complex scope in the audit trail if configuration changes are audited by the platform.

## Technical notes

- Add a persisted complex-scoped cancellation policy model or equivalent configuration storage.
- Add API endpoints to read and update the policy, for example:
  - `GET /api/v1/complexes/{complexId}/configuration/cancellation-policy`
  - `PUT /api/v1/complexes/{complexId}/configuration/cancellation-policy`
- Update `ICancellationPolicy` so it resolves the policy for the reservation's `SportsComplexId` rather than only reading global `CancellationPolicy` options.
- Preserve the existing global configuration as the fallback for complexes without an explicit policy.
- Add the configuration route and navigation entry under the complex admin layout.
- Reuse existing `RequireComplexAdmin` authorization and translation patterns.

## Out of scope

- Configuration of administrative cancellation rules.
- Configuration of policies for recurring reservation series.
- Other complex settings such as business hours, pricing, payments, notifications, or tax configuration.
- Global platform-wide policy management by super administrators.
