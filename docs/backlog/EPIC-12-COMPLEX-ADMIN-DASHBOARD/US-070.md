# US-070 — View and manage reservations from admin panel

## Status

Done

## Objective

As a complex administrator, I want to view and manage all reservations of my complex from the admin panel.

## Functional description

This user story enables the complex administrator to view, create, cancel, and update the status of reservations for their sports complex from the admin dashboard. It belongs to EPIC-12 — Complex Admin Dashboard.

## Acceptance criteria

- [x] Reservation list is implemented and available at `/admin/complex/:complexId/reservations`.
- [x] Results are filtered and paginated when applicable.
- [x] The list shows date, court, user, status, and time range.
- [x] Supports filtering by date, court, and status.
- [x] Allows cancellation with a reason.
- [x] Allows marking a reservation as completed or no-show.
- [x] Allows creating a manual reservation for a user.
- [x] Only authorized administrators can manage reservations of their complex.

## Business rules

- Create a single reservation.
- Query reservation details.
- List complex reservations for admins.
- Cancel reservations.
- Manual reservation creation by admins.
- Conflict prevention (no overlapping active reservations).
- Mark reservation as completed or no-show.
- Basic reservation history.
- Only authorized users can modify resources they own or administer.

## Validations

- Validate required fields and data types server-side.
- Validate query parameters and pagination inputs.
- Verify the actor has permission to update the resource.
- Return clear, structured error messages for invalid input.

## Error cases

- Invalid or missing input data.
- User is not authenticated or authorized.
- The referenced resource does not exist.
- The requested slot is no longer available.
- The cancellation deadline has passed.

## Security considerations

- Authenticate and authorize every mutating request.
- Do not expose internal implementation details in error responses.
- Avoid logging sensitive data such as passwords, tokens, or PII.
- Ensure users can only view data they are allowed to access (multi-tenancy).
- Verify the actor belongs to or administers the affected complex.

## Technical notes

- Reuse EPIC-06 reservation endpoints.
- If backend endpoints are not yet implemented, they must be added first.
- Implement filters and pagination with Material-UI components.
- Use modal dialogs for cancellation, status update, and manual creation.
