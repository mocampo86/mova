# US-067 — Create a court from admin panel

## Status

Done

## Objective

As a complex administrator, I want to create a court from the admin panel so I can expand my complex.

## Functional description

This user story enables the complex administrator to create a new court for their sports complex from the admin dashboard. It belongs to EPIC-12 — Complex Admin Dashboard.

## Acceptance criteria

- [x] Create court form is implemented and available at `/admin/complex/:complexId/courts/new`.
- [x] Required fields are validated before persistence.
- [x] The form captures name, description, surface type, indoor/outdoor flag, and optional sports.
- [x] The created resource is persisted and returned with an identifier.
- [x] Only authenticated and authorized users can create the resource.
- [x] After successful creation, the administrator is redirected to the court list.
- [x] Timestamps `CreatedAt` and `UpdatedAt` are tracked.

## Business rules

- CRUD for `Court`.
- Association of one or more `Sport` to a court.
- A court must have at least one active sport before it can accept reservations.
- Input validation must be enforced on the server, not only the client.
- Only authorized users can modify resources they own or administer.

## Validations

- Validate required fields and data types server-side.
- Enforce length, format, and range limits.
- Check uniqueness where applicable.
- Return clear, structured error messages for invalid input.

## Error cases

- Invalid or missing input data.
- User is not authenticated or authorized.
- The referenced resource does not exist.
- Duplicate or conflicting data violates uniqueness rules.

## Security considerations

- Authenticate and authorize every mutating request.
- Do not expose internal implementation details in error responses.
- Avoid logging sensitive data such as passwords, tokens, or PII.
- Sanitize and validate all user input to prevent injection attacks.
- Verify the actor belongs to or administers the affected complex.

## Technical notes

- Use `POST /api/v1/complexes/{complexId}/courts`.
- Reuse `CreateCourtRequest` contract and `CreateCourtCommandValidator` rules.
- Use `react-hook-form` with `zod` resolver.
- Fetch available sports from `GET /api/v1/sports`.

## Tests required

- **Unit**: domain logic and validation rules.
- **Integration**: API endpoint behavior and persistence.
- **E2E**: admin creates a court from the panel.
