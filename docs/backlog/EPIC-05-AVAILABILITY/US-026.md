# US-026 — List the courts of a complex

## Objective

As a user, I want to list the courts of a complex.

## Functional description

This user story enables the user to list the courts of a complex. It belongs to EPIC-05 — Public Availability and Discovery.

## Acceptance criteria

- [ ] List the courts of a complex is implemented and available to the user.
- [ ] Results are filtered and paginated when applicable.
- [ ] Only active and public resources are returned to unauthorized callers.
- [ ] Response times remain acceptable for mobile users.
- [ ] Only active complexes and courts are listed.

## Business rules

- Public landing page.
- List and detail views for complexes.
- List courts of a complex.
- Filter courts by sport.
- Availability query by date and court.
- Display upcoming available slots.

## Validations

- Validate required fields and data types server-side.
- Validate query parameters and pagination inputs.
- Return clear, structured error messages for invalid input.

## Error cases

- Invalid or missing input data.
- User is not authenticated or authorized.
- The referenced resource does not exist.
- No results match the filter criteria.

## Security considerations

- Authenticate and authorize every mutating request.
- Do not expose internal implementation details in error responses.
- Avoid logging sensitive data such as passwords, tokens, or PII.
- Ensure users can only view data they are allowed to access (multi-tenancy).
- Verify the actor belongs to or administers the affected complex.

## Technical notes

- Availability algorithm:
  1. Take the court's active `CourtAvailabilityRule` for the requested day of week.
  2. Split the range into slots of `SlotDurationMinutes`.
  3. Remove slots that overlap with active reservations or `CourtBlock` records.
  4. Remove slots outside the complex `BusinessHours` for that day.
- API: `GET /api/v1/complexes/{complexId}/availability?courtId=&date=`.
- All times stored in UTC; frontend converts to local time.
