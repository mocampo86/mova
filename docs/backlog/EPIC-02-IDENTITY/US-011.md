# US-011 — Protected routes in the React app

## Status

Done

## Objective

As a developer, I want protected routes in the React app so unauthorized users cannot access admin features.

## Functional description

This user story covers protected routes in the React app for the developer. The goal is that unauthorized users cannot access admin features. It belongs to EPIC-02 — Identity and Access.

## Acceptance criteria

- [x] Protected routes in the React app is implemented and available to the developer.
- [x] Unauthorized users are redirected away from protected routes.
- [x] Role-based access is verified before rendering admin pages.
- [x] Public routes remain accessible without authentication.
- [x] Users can log in via Google and receive a valid JWT.

## Business rules

- Google OpenID Connect integration.
- JWT issuance and validation.
- User profile completion with mandatory phone number.
- Roles and authorization policies.
- Protected routes and endpoints.
- Preparation for future phone verification.

## Validations

- Validate required fields and data types server-side.
- Return clear, structured error messages for invalid input.

## Error cases

- Invalid or missing input data.
- User is not authenticated or authorized.
- The referenced resource does not exist.

## Security considerations

- Authenticate and authorize every mutating request.
- Do not expose internal implementation details in error responses.
- Avoid logging sensitive data such as passwords, tokens, or PII.
- Enforce role checks on both the API and the UI routing layer.

## Technical notes

- Use ASP.NET Core `AddJwtBearer` and Google authentication.
- Store `GoogleSubjectId`, `Email`, `FullName`, `PhoneNumber`, and `PhoneVerified`.
- Custom `IAuthorizationRequirement` for complex-scoped access.
- Frontend stores access token in memory and refresh token in `HttpOnly` cookie if implemented.

## Tests required

- **Unit**: domain logic and validation rules.
- **Integration**: API endpoint behavior and persistence.
- **E2E**: user flow through the frontend.

## Out of scope

- Features explicitly listed in later epics or future sprints.
- Advanced analytics, reporting, or notifications not required for the MVP.
