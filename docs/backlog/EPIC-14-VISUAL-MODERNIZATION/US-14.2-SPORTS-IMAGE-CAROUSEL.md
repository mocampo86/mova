# US-14.2 — Implement a Sports Image Carousel

## Status

Proposed — awaiting human review.

## Objective

As a MOVA visitor, I want to see different sports facilities and activities on the homepage, so that I can quickly identify the types of experiences available through the platform.

## Functional description

Add a sports-focused image carousel to the homepage hero experience. It represents the facility and activity types named by the epic while ensuring the hero message and primary CTAs remain readable on every displayed image.

## Acceptance criteria

- [ ] Given a visitor opens the homepage, when the hero is displayed, then sports and facility imagery is available as part of the visual experience.
- [ ] Given multiple carousel images are configured, when the carousel advances, then the currently displayed visual changes without obscuring the hero text or CTAs.
- [ ] Given a visitor uses the carousel controls, when a control is activated, then the selected visual is displayed.
- [ ] Given a keyboard user interacts with the carousel, when controls receive focus or are activated, then each control has an accessible name, visible focus state, and keyboard operation.
- [ ] Given animation is reduced by the visitor's system preference, when the hero loads, then carousel motion does not run automatically.
- [ ] Given the carousel is viewed on desktop, tablet, or mobile, when it adapts to the viewport, then image treatment remains performant and content remains readable.

## Business rules

- Imagery must represent sports, courts, or sports complexes and must not alter the booking or discovery business flow.
- The hero's value proposition and primary CTAs take visual precedence over the imagery.
- Images must have appropriate text alternatives when they convey information; decorative visuals must not create duplicate screen-reader content.

## Validations

- Verify every configured asset is suitable for web delivery and has an explicit semantic purpose decision (informative alternative text or decorative treatment).
- Verify controls do not rely on color alone and remain usable by keyboard.
- Verify automatic motion respects reduced-motion preferences.

## Error cases

- If an image fails to load, the carousel controls, hero message, and CTAs remain usable; no error state blocks the landing page.
- If only one image is configured, carousel navigation and auto-advance are not presented as available actions.

## Security considerations

- Use approved static assets or public asset delivery that does not expose user information or credentials.
- No API, authentication, authorization, or persistence changes are included.

## Technical notes

- Affected area: the homepage and a reusable, typed frontend component under `components/` or the relevant feature boundary.
- The current project uses React 18, MUI, TypeScript, and Vitest; no carousel dependency is presently installed.
- Prefer a small accessible implementation using existing dependencies unless review approves an additional library.
- Optimize asset dimensions and loading strategy to maintain reasonable landing-page load time.

## Technical subtasks

- **TASK-14.2.1 — Define typed carousel content**: Create a localized/configurable list of approved sports visual assets and their accessibility treatment. **Done when:** the component accepts validated slide data without hard-coded UI duplication. **Testing:** unit coverage for configured slide behavior. **Dependencies:** approved visual assets. **Sequence:** BLOCKING.
- **TASK-14.2.2 — Create the accessible carousel presentation**: Implement the reusable carousel, readable overlay, and manual controls within the modernized hero. **Done when:** slides and controls are semantically exposed and hero content remains readable. **Testing:** React Testing Library coverage for controls and accessible names. **Dependencies:** TASK-14.2.1, US-14.1. **Sequence:** BLOCKING.
- **TASK-14.2.3 — Add motion and responsive behavior**: Add optional timed progression, reduced-motion handling, and viewport-safe sizing. **Done when:** motion is controlled and responsive behavior is stable. **Testing:** fake-timer and media-preference component tests plus manual viewport checks. **Dependencies:** TASK-14.2.2. **Sequence:** BLOCKING.
- **TASK-14.2.4 — Optimize and verify assets**: Apply appropriate image loading and validate visual quality and performance. **Done when:** assets do not impose avoidable load cost and failures preserve essential hero content. **Testing:** manual network/performance inspection. **Dependencies:** TASK-14.2.1, TASK-14.2.3. **Sequence:** PARALLELIZABLE with final visual polish.

## Tests required

- **Unit/component:** initial slide, manual controls, one-slide behavior, reduced motion, accessible names, and preserved CTAs.
- **Manual responsive/accessibility:** Verify focus order, contrast, alternative-text decision, desktop/tablet/mobile layouts, and failed-image fallback.

## Out of scope

- A CMS, user-uploaded images, personalized imagery, analytics tracking, video, or a full media-management capability.
- Changes to booking, authentication, authorization, database schema, or backend APIs.

## Dependencies

- US-14.1 — Modernize the Hero Section.
- Approved rights-cleared sports visual assets and US-14.5 visual tokens.

## Definition of Done

- All acceptance criteria pass with supported imagery and a safe failure path.
- Relevant frontend tests, linting, and build pass.
- Image loading is reviewed for reasonable size and behavior.
- Human review approval is obtained before implementation.
