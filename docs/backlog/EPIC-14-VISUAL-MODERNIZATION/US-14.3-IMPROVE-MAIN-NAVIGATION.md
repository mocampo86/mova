# US-14.3 — Improve Main Navigation

## Status

Proposed — awaiting human review.

## Objective

As a MOVA user, I want clear and consistent navigation, so that I can easily access the platform's main features.

## Functional description

Modernize the public header and navigation presentation while retaining clear access to the homepage, user login, administrator login, and language selector. Authenticated header behavior must remain compatible with its current dashboard and logout actions.

## Acceptance criteria

- [ ] Given a visitor views a public page, when the header is displayed, then the MOVA brand links to the homepage and user login, administrator login, and language controls are available.
- [ ] Given an authenticated user views the header, when it is displayed, then existing dashboard, language, and logout actions remain available according to the current behavior.
- [ ] Given a visitor activates a navigation action, when navigation completes, then the existing target route and query intent are preserved.
- [ ] Given the navigation is viewed on mobile, when horizontal space is constrained, then its actions remain available without clipping or overlap.
- [ ] Given a keyboard or assistive-technology user uses the header, when controls receive focus, then they have visible focus states and accessible names.

## Business rules

- Preserve existing login intent routes, language selection, dashboard access, and logout behavior.
- Do not add or remove authorization capabilities through visual navigation changes.
- The active location should be identifiable when a navigation item represents a current page.

## Validations

- Verify public versus authenticated actions match existing authorization state.
- Verify the mobile presentation retains all required public navigation actions.
- Verify brand and control labels are supplied through the existing localization system.

## Error cases

- If translated labels are unavailable, existing i18n fallback behavior must keep controls understandable.

## Security considerations

- Do not surface protected administrative destinations to unauthorized users beyond existing behavior.
- Preserve the existing logout mechanism; do not handle tokens or credentials in visual components.

## Technical notes

- Affected area: `src/mova-web/src/layouts/AppHeader.tsx`, `PublicLayout.tsx`, `LanguageSelector`, existing routes, and shared MUI theme.
- `AppHeader` already differentiates authenticated and visitor actions and uses MUI breakpoint handling; evolve this behavior rather than replace it.

## Technical subtasks

- **TASK-14.3.1 — Establish navigation hierarchy**: Rework header layout and responsive grouping around existing controls. **Done when:** branding and required actions are consistently prioritized. **Testing:** header component tests for visitor and authenticated states. **Dependencies:** US-14.5 tokens. **Sequence:** BLOCKING.
- **TASK-14.3.2 — Implement mobile-safe navigation**: Adapt the existing MUI breakpoint behavior so required actions remain operable on narrow screens. **Done when:** controls are not clipped or overlapped. **Testing:** component tests and manual responsive checks. **Dependencies:** TASK-14.3.1. **Sequence:** BLOCKING.
- **TASK-14.3.3 — Verify navigation accessibility and routing**: Confirm semantic labels, focus visibility, focus order, and existing route/query behavior. **Done when:** keyboard and navigation regressions are covered. **Testing:** React Testing Library tests. **Dependencies:** TASK-14.3.1, TASK-14.3.2. **Sequence:** BLOCKING.

## Tests required

- **Component:** visitor and authenticated action visibility, homepage link, existing login intents, dashboard, logout, and language selector.
- **Manual responsive/accessibility:** inspect narrow viewport layout and keyboard focus/order.

## Out of scope

- New navigation destinations, user roles, authentication flows, or changes to protected-route enforcement.
- A new global information architecture or sidebar redesign for user and complex-admin layouts.

## Dependencies

- Existing `AppHeader`, `LanguageSelector`, React Router routes, and authentication provider.
- US-14.5 — Create a Reusable Visual Design System.

## Definition of Done

- All acceptance criteria are verified without changing navigation meaning or authorization.
- Relevant frontend tests, linting, and build pass.
- Human review approval is obtained before implementation.
