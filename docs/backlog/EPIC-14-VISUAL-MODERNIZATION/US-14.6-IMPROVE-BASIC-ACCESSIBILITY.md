# US-14.6 — Improve Basic Accessibility

## Status

Proposed — awaiting human review.

## Objective

As a MOVA user, I want to navigate and interact with the interface in an accessible way, so that I can use the main features regardless of my device or interaction method.

## Functional description

Improve foundational accessibility for Epic 14's public visual scope: contrast, keyboard navigation, focus states, alternative text, semantic HTML, and screen-reader compatibility. Validate the modernized landing page, hero carousel, and main navigation without expanding into unrelated functional redesigns.

## Acceptance criteria

- [ ] Given a keyboard user visits the public homepage, when they move through interactive controls, then focus order is logical and every focusable control has a visible focus indicator.
- [ ] Given a screen-reader user visits the public homepage, when sections, headings, navigation controls, CTAs, and informative imagery are announced, then their purpose is understandable from semantic HTML and accessible names.
- [ ] Given sports imagery is displayed, when it is informative, then it has an appropriate alternative text; when it is decorative, then it is excluded from redundant announcements.
- [ ] Given text and interactive controls are rendered in the modernized public experience, when they are viewed in their normal and focus states, then foreground and background contrast supports readability.
- [ ] Given a carousel is present, when a user interacts with it by keyboard or screen reader, then manual controls are operable and automatic motion respects reduced-motion preferences.

## Business rules

- Accessibility improvements must preserve existing routes, booking behavior, language support, and authentication behavior.
- Semantic markup and accessible names must describe the control's purpose rather than its visual appearance alone.
- Do not add accessibility overlays or automated remediation widgets as substitutes for accessible implementation.

## Validations

- Perform keyboard-only navigation through the public header, hero CTAs, and carousel controls.
- Inspect headings, landmark structure, names, roles, alternative text, and contrast with browser accessibility tooling or an equivalent manual process.
- Verify reduced-motion behavior introduced in US-14.2.

## Error cases

- If a decorative image fails or is unavailable, it must not leave an unlabeled control or remove essential text content.
- If localization length changes labels, accessible names must remain meaningful and controls must remain reachable.

## Security considerations

- Accessibility labels must not reveal account details, tokens, or protected information.
- This story does not change authorization, authentication, backend APIs, or stored data.

## Technical notes

- Affected area: `HomePage`, carousel component introduced by US-14.2, `AppHeader`, `LanguageSelector` integration, MUI theme, and corresponding tests.
- Existing public home sections already use semantic section headings and `aria-labelledby`; retain and extend those patterns.
- Use MUI's accessible controls and native semantic elements where possible; do not add a dependency unless separately approved.

## Technical subtasks

- **TASK-14.6.1 — Audit Epic 14 public interaction paths**: Review current and planned landmarks, headings, focus order, names, imagery, and contrast. **Done when:** findings are mapped to the story acceptance criteria. **Testing:** keyboard and screen-reader/tooling review. **Dependencies:** US-14.1, US-14.2, US-14.3, US-14.5. **Sequence:** BLOCKING for final accessibility sign-off.
- **TASK-14.6.2 — Remediate semantic, focus, and contrast gaps**: Update the relevant shared theme and public components according to audit findings. **Done when:** each identified Epic 14 gap is resolved without changing business behavior. **Testing:** component tests for roles/names and manual checks. **Dependencies:** TASK-14.6.1. **Sequence:** BLOCKING.
- **TASK-14.6.3 — Add accessibility regression coverage**: Extend component tests for important headings, CTA/control names, keyboard-operable controls, and decorative/informative image treatment. **Done when:** key accessible behavior is protected by tests. **Testing:** Vitest/React Testing Library plus manual assistive-technology validation. **Dependencies:** TASK-14.6.2. **Sequence:** BLOCKING.

## Tests required

- **Component:** semantic headings/landmarks, CTA/control accessible names, focus-visible styles where testable, image alternative-text treatment, and carousel controls.
- **Manual accessibility:** keyboard-only path, screen-reader or accessibility-tree inspection, contrast check, and reduced-motion check across responsive viewports.

## Out of scope

- A formal external accessibility certification, accessibility remediation of every authenticated page, assistive-technology support outside the Epic 14 scope, or a new accessibility overlay product.
- Changes to backend APIs, data model, booking workflow, authentication, or authorization.

## Dependencies

- US-14.1 — Modernize the Hero Section.
- US-14.2 — Implement a Sports Image Carousel.
- US-14.3 — Improve Main Navigation.
- US-14.4 — Implement Responsive Design.
- US-14.5 — Create a Reusable Visual Design System.

## Definition of Done

- All acceptance criteria pass through automated and documented manual validation.
- Relevant frontend tests, linting, and build pass.
- No accessibility regression is introduced in public navigation or homepage CTAs.
- Human review approval is obtained before implementation.
