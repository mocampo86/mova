# US-14.1 — Modernize the Hero Section

## Status

Proposed — awaiting human review.

## Objective

As a MOVA visitor, I want to see a modern and attractive homepage, so that I can quickly understand what the platform offers and which actions I can perform.

## Functional description

Refresh the landing-page hero so it clearly communicates MOVA's sports-facility discovery and booking value proposition. Keep the existing player, complex-manager, and browsing entry points available and visually prioritized.

## Acceptance criteria

- [ ] Given a visitor opens the homepage, when the hero is displayed, then it presents MOVA's value proposition and sports-related visual content.
- [ ] Given the hero is displayed, when a visitor views its actions, then the play/book, manage-complex, and browse-complexes CTAs are visible and distinguishable.
- [ ] Given a visitor activates a hero CTA, when navigation completes, then it reaches the existing intended route.
- [ ] Given the hero is viewed at desktop, tablet, or mobile width, when the layout adapts, then its text and CTAs remain readable, operable, and do not overlap.
- [ ] Given a keyboard user tabs through the hero, when each interactive CTA receives focus, then a visible focus indicator is present.

## Business rules

- Preserve the existing destination and authorization behavior of all CTAs.
- The visual treatment must support, not obscure, the hero's primary message and actions.
- Content remains available through localized strings; this story does not change supported languages.

## Validations

- Verify CTA destinations continue to match their existing routes.
- Verify text and actionable controls retain sufficient contrast against the selected visual background or overlay.
- Verify the hero has one semantic page-level heading.

## Error cases

- If an optional hero visual asset cannot be displayed, the value proposition and CTAs must remain available and readable.

## Security considerations

- No authentication, authorization, API, or data-model behavior changes are permitted.
- Do not add external assets that require exposing credentials or user data.

## Technical notes

- Affected area: `src/mova-web/src/pages/HomePage.tsx`, existing i18n resources, and the shared MUI theme where required.
- Reuse React, MUI, React Router, and `react-i18next`; do not introduce a dependency solely for this visual change.
- Use a non-text fallback or CSS treatment that does not make essential content dependent on imagery.

## Technical subtasks

- **TASK-14.1.1 — Define hero visual composition**: Update the existing home-page hero structure to support the approved visual hierarchy while preserving semantic heading and CTA content. **Done when:** the hero has an intentional, responsive composition. **Testing:** update component tests for heading and CTA presence. **Dependencies:** none. **Sequence:** BLOCKING.
- **TASK-14.1.2 — Apply readable responsive hero styling**: Use the shared MUI theme and responsive `sx` conventions to style the hero, CTAs, and visual overlay. **Done when:** the hero is legible at supported widths with visible focus treatment. **Testing:** component and manual responsive checks. **Dependencies:** TASK-14.1.1. **Sequence:** BLOCKING.
- **TASK-14.1.3 — Validate existing hero behavior**: Extend `HomePage` tests to verify existing destinations and the modernized semantic content. **Done when:** hero behavior is covered without changing routes. **Testing:** Vitest/React Testing Library. **Dependencies:** TASK-14.1.1, TASK-14.1.2. **Sequence:** BLOCKING.

## Tests required

- **Component:** Homepage renders the value proposition, semantic heading, and all existing CTA routes.
- **Manual responsive/accessibility:** Inspect desktop, tablet, and mobile layouts; keyboard-tab through each CTA and assess contrast.

## Out of scope

- Sports image carousel behavior (US-14.2).
- New landing-page routes, booking-workflow changes, authentication changes, or backend changes.
- Copywriting changes beyond what is necessary to preserve existing localized content.

## Dependencies

- Existing public `HomePage`, public layout, routes, and localization resources.
- US-14.5 provides the shared visual-token foundation; this story may be implemented after it or use its approved tokens.

## Definition of Done

- All acceptance criteria are verifiable and pass.
- Relevant frontend tests, linting, and build pass.
- No regression is introduced to existing CTA destinations, i18n, or authentication flow.
- Human review approval is obtained before implementation.
