# US-073 — View reservations in a daily calendar with color-coded slots

## Status

Ready

## Objective

As a complex administrator, I want to view reservations for a selected day in a calendar layout so I can quickly identify free and occupied time slots.

## Functional description

This user story adds a daily calendar view to the complex reservation management screen. The administrator can switch between the existing list view and the new calendar view. The calendar displays time slots grouped by court and uses color coding to distinguish free slots from reserved slots and to indicate the reservation status. A visible color reference explains the meaning of each color.

## Acceptance criteria

- [ ] A daily calendar view is available on the complex reservations page.
- [ ] The administrator can switch between list view and calendar view without losing the selected date or court filter.
- [ ] The administrator can select a date to display in the calendar.
- [ ] The calendar can be filtered by a single court or show all courts of the complex.
- [ ] Time slots align with the configured `SlotDurationMinutes` for each court.
- [ ] Free slots are clearly distinguishable from reserved slots.
- [ ] Reserved slots are colored according to their status.
- [ ] A color reference legend is always visible on the calendar view.
- [ ] Selecting a slot or reservation opens its details and available actions.
- [ ] Only reservations belonging to the current complex are shown.
- [ ] Response times remain acceptable for mobile users.

## Business rules

- Only authenticated `ComplexAdmin` or `SuperAdmin` users can access the calendar view.
- Reservations are linked to a court, a user, a complex, and a time range.
- Two active reservations cannot overlap on the same court.
- Manual reservations created by admins bypass public availability but still check conflicts.
- A slot is considered free when it is within the court availability rules and does not overlap with an active reservation or a blocked time range.

## Validations

- Validate the selected date and optional court filter.
- Validate the user is authorized for the requested complex.
- Validate query parameters and pagination inputs where applicable.
- Return clear, structured error messages for invalid input.

## Error cases

- Invalid or missing input data.
- User is not authenticated or authorized for the complex.
- The referenced complex or court does not exist.
- No availability rules are configured for the selected day.
- No results match the filter criteria.

## Security considerations

- Authenticate and authorize every request.
- Do not expose internal implementation details in error responses.
- Avoid logging sensitive data such as passwords, tokens, or PII.
- Ensure users can only view data they are allowed to access (multi-tenancy).

## Technical notes

- Reuse `GET /api/v1/complexes/{complexId}/reservations` to obtain reservations for the selected date and court.
- Reuse `GET /api/v1/complexes/{complexId}/availability?courtId={courtId}&date={date}` to obtain free slots per court.
- All times are stored in UTC; the frontend converts them to local time for display.
- For an all-courts view, aggregate availability per court on the frontend or extend the availability endpoint if performance requires it.
- Status values: `Pending`, `Confirmed`, `CancelledByUser`, `CancelledByAdmin`, `Completed`, `NoShow`.
- `Reservation` entity: `Id`, `SportsComplexId`, `CourtId`, `UserId`, `StartAt`, `EndAt`, `Status`, `Source`, `RecurringReservationId`, `Notes`, `CreatedAt`, `CancelledAt`, `CancellationReason`.

## Color reference

The following semantic color mapping is proposed for the daily calendar view:

| Visual state | Meaning | Suggested MUI token | Suggested color |
|--------------|---------|---------------------|-----------------|
| Free / Available | Time slot with no reservation | `success.main` | Green |
| Confirmed | Confirmed reservation | `primary.main` | Blue |
| Pending | Pending reservation | `warning.main` | Orange |
| Cancelled (by user or admin) | Cancelled reservation | `error.main` | Red |
| Completed | Reservation that was attended | `info.main` | Cyan |
| NoShow | Reservation where the user did not attend | `text.secondary` | Grey |

The final palette must be consistent with the existing reservation status chip colors used in the list view. If the theme is customized later, update the mapping to use the corresponding theme tokens.
