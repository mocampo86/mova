# US-032 — Cancel a reservation according to the cancellation policy

## Status

Ready

## Objective

As a user, I want to cancel a reservation according to the cancellation policy.

## Functional description

This user story enables the user to cancel a reservation according to the cancellation policy. It belongs to EPIC-06 — Reservations.

## Acceptance criteria

- [ ] Cancel a reservation according to the cancellation policy is implemented and available to the user.
- [ ] Cancellation follows the configured cancellation policy.
- [ ] Status transition is valid and recorded with a reason when required.
- [ ] The freed slot becomes available again.
- [ ] A reservation is linked to a court, a user, a complex, and a time range.
- [ ] Users can cancel their own reservations before the configured deadline.
- [ ] Admins can cancel any reservation in their complex and record a reason.

## Business rules

- Create a single reservation.
- Query reservation details.
- List user's reservations.
- List complex reservations for admins.
- Cancel reservations.
- Manual reservation creation by admins.
- Conflict prevention (no overlapping active reservations).
- Mark reservation as completed or no-show.
- Basic reservation history.
- Only authorized users can modify resources they own or administer.

## Validations

- Validate required fields and data types server-side.
- Return clear, structured error messages for invalid input.

## Error cases

- Invalid or missing input data.
- User is not authenticated or authorized.
- The referenced resource does not exist.
- The cancellation deadline has passed.

## Security considerations

- Authenticate and authorize every mutating request.
- Do not expose internal implementation details in error responses.
- Avoid logging sensitive data such as passwords, tokens, or PII.

## Technical notes

- `Reservation` entity: `Id`, `SportsComplexId`, `CourtId`, `UserId`, `StartAt`, `EndAt`, `Status`, `Source`, `RecurringReservationId`, `Notes`, `CreatedAt`, `CancelledAt`, `CancellationReason`.
- Status values: `Pending`, `Confirmed`, `CancelledByUser`, `CancelledByAdmin`, `Completed`, `NoShow`.
- For the MVP, reservations made by users are auto-confirmed.
- Cancellation policy is global or per-complex; default is a minimum number of hours before the slot.
- Concurrency protection: serializable transaction or advisory lock per `(CourtId, StartAt)`.
