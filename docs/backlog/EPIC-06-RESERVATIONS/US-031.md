# US-031 — View my reservation history

## Status

Done

## Objective

As a user, I want to view my reservation history.

## Functional description

This user story enables the user to view my reservation history. It belongs to EPIC-06 — Reservations.

## Acceptance criteria

- [x] View my reservation history is implemented and available to the user.
- [x] Results are filtered and paginated when applicable.
- [x] Only active and public resources are returned to unauthorized callers.
- [ ] Response times remain acceptable for mobile users.
- [x] A reservation is linked to a court, a user, a complex, and a time range.
- [x] Admins can cancel any reservation in their complex and record a reason.
- [x] Cancelled reservations in history display the cancellation reason and the actor (`cancelledByUserId` / `cancelledByUserName`).

## Business rules

- Create a single reservation.
- Query reservation details.
- List user's reservations.
- List complex reservations for admins.
- Cancel reservations.
- Manual reservation creation by admins.
- Conflict prevention (no overlapping active reservations).
- Mark reservation as completed or no-show.
- Basic reservation history.

## Validations

- Validate required fields and data types server-side.
- Validate query parameters and pagination inputs.
- Return clear, structured error messages for invalid input.

## Error cases

- Invalid or missing input data.
- User is not authenticated or authorized.
- The referenced resource does not exist.
- No results match the filter criteria.

## Security considerations

- Authenticate and authorize every mutating request.
- Do not expose internal implementation details in error responses.
- Avoid logging sensitive data such as passwords, tokens, or PII.
- Ensure users can only view data they are allowed to access (multi-tenancy).

## Technical notes

- `Reservation` entity: `Id`, `SportsComplexId`, `CourtId`, `UserId`, `StartAt`, `EndAt`, `Status`, `Source`, `RecurringReservationId`, `Notes`, `CreatedAt`, `CancelledAt`, `CancellationReason`, `CancelledByUserId`.
- Status values: `Pending`, `Confirmed`, `CancelledByUser`, `CancelledByAdmin`, `Completed`, `NoShow`.
- For the MVP, reservations made by users are auto-confirmed.
- User cancellation policy is resolved from the reservation's complex configuration (US-075), with the global `CancellationPolicy` configuration as fallback. Cancellation history preserves the result of the policy applied at cancellation time.
- Concurrency protection: serializable transaction or advisory lock per `(CourtId, StartAt)`.
