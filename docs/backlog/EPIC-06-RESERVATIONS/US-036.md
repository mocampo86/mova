# US-036 — Mark a reservation as completed or no-show

## Status

Done

## Objective

As an administrator, I want to mark a reservation as completed or no-show.

## Functional description

This user story enables the administrator to mark a reservation as completed or no-show. It belongs to EPIC-06 — Reservations.

## Acceptance criteria

- [x] Mark a reservation as completed or no-show is implemented and available to the administrator.
- [x] The reservation is linked to a court, user, complex, and time range.
- [x] Overlapping active reservations on the same court are prevented.
- [x] Reservation is confirmed immediately for the MVP.
- [x] A reservation is linked to a court, a user, a complex, and a time range.
- [x] Admins can cancel any reservation in their complex and record a reason.

## Business rules

- Create a single reservation.
- Query reservation details.
- List user's reservations.
- List complex reservations for admins.
- Cancel reservations.
- Manual reservation creation by admins.
- Conflict prevention (no overlapping active reservations).
- Mark reservation as completed or no-show.
- Basic reservation history.
- Two active reservations cannot overlap on the same court.

## Validations

- Validate required fields and data types server-side.
- Verify the court exists and is active.
- Verify the slot is not already reserved.
- Apply the cancellation policy for cancel operations.
- Return clear, structured error messages for invalid input.

## Error cases

- Invalid or missing input data.
- User is not authenticated or authorized.
- The referenced resource does not exist.
- The requested slot is no longer available.
- The court is inactive.

## Security considerations

- Authenticate and authorize every mutating request.
- Do not expose internal implementation details in error responses.
- Avoid logging sensitive data such as passwords, tokens, or PII.

## Technical notes

- `Reservation` entity: `Id`, `SportsComplexId`, `CourtId`, `UserId`, `StartAt`, `EndAt`, `Status`, `Source`, `RecurringReservationId`, `Notes`, `CreatedAt`, `CancelledAt`, `CancellationReason`.
- Status values: `Pending`, `Confirmed`, `CancelledByUser`, `CancelledByAdmin`, `Completed`, `NoShow`.
- For the MVP, reservations made by users are auto-confirmed.
- User cancellation policy is configured per complex through US-075, with global `CancellationPolicy` values as fallback. Marking attendance and administrative cancellation remain separate operations.
- Concurrency protection: serializable transaction or advisory lock per `(CourtId, StartAt)`.
