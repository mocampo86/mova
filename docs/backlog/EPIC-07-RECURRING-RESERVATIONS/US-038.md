# US-038 — Create recurring reservations for customers

## Objective

As an administrator, I want to create recurring reservations for customers.

## Functional description

This user story enables the administrator to create recurring reservations for customers. It belongs to EPIC-07 — Recurring Reservations.

## Acceptance criteria

- [ ] Create recurring reservations for customers is implemented and available to the administrator.
- [ ] Required fields are validated before persistence.
- [ ] The created resource is persisted and returned with an identifier.
- [ ] Only authenticated and authorized users can create the resource.
- [ ] Timestamps `CreatedAt` and `UpdatedAt` are tracked.
- [ ] A recurring reservation has `DayOfWeek`, `StartTime`, `DurationMinutes`, `StartDate`, and `EndDate`.
- [ ] Individual reservations are generated for each occurrence.
- [ ] Generated occurrences respect existing reservations and blocks.

## Business rules

- Create a weekly recurring reservation rule.
- Validate availability across the recurrence period.
- Generate individual `Reservation` occurrences.
- Cancel a single occurrence.
- Cancel the entire series.
- Modify future occurrences without affecting history.
- Detect conflicts during generation.
- Input validation must be enforced on the server, not only the client.
- Only authorized users can modify resources they own or administer.

## Validations

- Validate required fields and data types server-side.
- Enforce length, format, and range limits.
- Check uniqueness where applicable.
- Verify the actor has permission to create or update the resource.
- Return clear, structured error messages for invalid input.

## Error cases

- Invalid or missing input data.
- User is not authenticated or authorized.
- The referenced resource does not exist.
- Duplicate or conflicting data violates uniqueness rules.

## Security considerations

- Authenticate and authorize every mutating request.
- Do not expose internal implementation details in error responses.
- Avoid logging sensitive data such as passwords, tokens, or PII.
- Sanitize and validate all user input to prevent injection attacks.

## Technical notes

- `RecurringReservation` entity: `Id`, `SportsComplexId`, `CourtId`, `UserId`, `DayOfWeek`, `StartTime`, `DurationMinutes`, `StartDate`, `EndDate`, `Status`, `CreatedAt`.
- Each occurrence creates a `Reservation` with `Source = Recurring` and `RecurringReservationId` populated.
- Generation must be transactional and conflict-aware.
- Consider a background or scheduled task if generation becomes expensive; for the MVP, synchronous generation is acceptable for reasonable ranges.
