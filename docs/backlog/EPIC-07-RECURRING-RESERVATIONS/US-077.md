# US-077 — Admin recurring reservation list and series cancellation UI

## Status

Done

## Objective

As a complex administrator, I want to discover and manage recurring reservations for my complex, including cancelling an entire recurring series.

## Functional description

This user story delivers the admin-facing UI required to exercise the existing recurring-series cancellation capability introduced in US-040. Complex administrators can view all recurring reservation series for their complex, filter the list, and cancel a series either from the dedicated recurring-reservations list or inline from the existing reservations list. This story belongs to EPIC-07 — Recurring Reservations.

## Acceptance criteria

- [x] A complex administrator can view a paginated list of recurring reservation series for their complex.
- [x] The list displays the day of week, start time, duration, court, customer, period, status, and available actions.
- [x] The list supports filtering by customer, court, and status.
- [x] The list supports sorting by created date, start date, court name, and customer name.
- [x] A complex administrator can cancel an entire active recurring series from the dedicated list.
- [x] A complex administrator can cancel an entire active recurring series inline from `ComplexReservationsPage` when a reservation belongs to a series.
- [x] Cancelling a series opens a confirmation dialog that shows relevant series context and accepts an optional reason.
- [x] After cancellation, the series status and all future occurrences are updated to `Cancelled` / `CancelledByAdmin`.
- [x] Cancelling a series frees the affected slots so they become available again.
- [x] The dedicated list page provides a button to create a new recurring reservation.
- [x] The recurring reservation creation page (`/admin/complex/:complexId/recurring/new`) provides a cancel button that returns to the list.
- [x] All labels and messages are localized in English, Spanish, and Portuguese.
- [x] Only authorized complex administrators can access the list and cancellation endpoints.

## Business rules

- Recurring reservation management is available to complex administrators only.
- The cancellation follows the complex cancellation policy with the global fallback defined for the application.
- A series can only be cancelled while it is `Active`.
- Cancelling a series must not delete historical occurrences; it must update future occurrence statuses.
- Filter and sort parameters are optional and use sensible defaults.

## Validations

- Validate the complex identifier and pagination parameters server-side.
- Validate that the referenced recurring series exists and belongs to the requested complex.
- Validate that the actor is an active administrator of the complex for list and cancellation operations.
- Return clear, structured error messages for invalid input or unauthorized access.

## Error cases

- User is not authenticated.
- User is not an administrator of the requested complex.
- The referenced sports complex does not exist.
- The recurring reservation series does not exist.
- The recurring reservation series is not in a cancellable state.

## Security considerations

- Authenticate and authorize every request.
- Enforce complex scoping on the list endpoint.
- Do not expose internal implementation details in error responses.
- Avoid logging sensitive data such as tokens or PII.

## Technical notes

- Backend: new `GET /api/v1/complexes/{complexId}/recurring-reservations` endpoint restricted to `AuthorizationPolicies.ComplexAdmin`.
- Backend: new `GetRecurringReservationsByComplexQuery`, handler, validator, and repository method with pagination, filtering, and sorting.
- Backend: `RecurringReservationListItem` contract includes court and customer display names.
- Frontend: new `AdminRecurringReservationsListPage` at `/admin/complex/:complexId/recurring`.
- Frontend: existing admin creation page moved to `/admin/complex/:complexId/recurring/new`.
- Frontend: new `RecurringReservationCancelDialog` shared between the list and inline actions.
- Frontend: new `useRecurringReservations` and `useCancelRecurringReservation` hooks with TanStack Query cache invalidation.
- Frontend: inline "Cancel series" action added to `ComplexReservationsPage` for reservations with a `recurringReservationId`.
