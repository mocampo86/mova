# US-076 — Configure user recurring reservation availability

## Status

Ready

## Objective

As a complex administrator, I want to enable or disable recurring reservations for users from the admin panel.

## Functional description

This user story enables complex administrators to control whether regular users can create recurring reservations for a sports complex. The setting belongs to EPIC-07 — Recurring Reservations and applies to user self-service booking flows.

**Important:** Complex administrators are NOT affected by this setting and can ALWAYS create recurring reservations regardless of the configuration value.

## Acceptance criteria

- [ ] A complex administrator can enable or disable user-created recurring reservations from the admin panel.
- [ ] The setting is stored per sports complex.
- [ ] When disabled, **regular users** cannot create recurring reservations for that complex.
- [ ] When disabled, **regular users** receive a clear, structured error message explaining that recurring reservations are not available for the complex.
- [ ] When enabled, **regular users** can create recurring reservations if all existing recurring reservation validations pass.
- [ ] **Complex administrators can ALWAYS create recurring reservations regardless of the setting value.**
- [ ] Existing recurring reservations are not automatically cancelled when the setting is disabled.
- [ ] Complex administrators can still view the current setting after saving changes.
- [ ] Only authorized administrators of the complex can update the setting.
- [ ] **In the user booking panel, the recurring reservation option should be hidden or visually disabled when the complex does not allow user recurring reservations.**

## Business rules

- The setting controls **user self-service** recurring reservation creation ONLY.
- **Administrators are NOT affected by this setting and can always create recurring reservations.**
- The setting must be evaluated before generating recurring reservation occurrences for **user** requests.
- Disabling the setting does not affect single reservations.
- Disabling the setting does not modify historical or future occurrences that already exist.
- The default value for existing complexes must be defined explicitly by the implementation.
- Administrator-created recurring reservations are **ALWAYS allowed** and out of scope of this restriction.
- **The frontend should conditionally render/hide the recurring reservation option based on the setting value.**

## Validations

- Validate the setting payload server-side.
- Verify the sports complex exists.
- Verify the actor is an active administrator of the sports complex **for update operations**.
- **For recurring reservation creation:**
  - If the user is an administrator → ALLOW (skip the setting check)
  - If the user is a regular user → check the `AllowUserRecurringReservations` setting
- Return clear, structured error messages for invalid input or unauthorized access.

## Error cases

- User is not authenticated.
- User is not authorized to manage the complex (for update operations).
- The referenced sports complex does not exist.
- The request payload is invalid.
- A **regular user** attempts to create a recurring reservation while user recurring reservations are disabled.
- An administrator attempting to create a recurring reservation should NEVER receive this error.

## Security considerations

- Authenticate and authorize every mutating request.
- Do not trust the frontend to enforce the setting.
- Enforce the setting in the backend recurring reservation creation handler.
- Do not expose internal implementation details in error responses.
- Avoid logging sensitive data such as tokens or PII.

## Technical notes

- Add a per-complex configuration field or settings entity, for example `AllowUserRecurringReservations`.
- Expose an admin API to read and update the setting for a complex.
- The user recurring reservation creation endpoint must reject requests when the setting is disabled.
- The admin recurring reservation creation endpoint MUST NOT reject requests when the setting is disabled.
- The admin panel should show the setting as a toggle in the complex configuration area.
- Consider including the value in any existing complex configuration response if one exists.
- **The frontend user panel should fetch the complex settings and conditionally render the recurring reservation option.**

## Tests required

- **Unit**: validation rules for the configuration command.
- **Unit**: recurring reservation creation rejects **regular user** requests when disabled.
- **Unit**: recurring reservation creation ALWAYS allows **administrator** requests even when disabled.
- **Integration**: admin can update and read the setting for their complex.
- **Integration**: unauthorized users cannot update the setting.
- **Integration**: **regular user** recurring reservation creation returns conflict or forbidden when disabled.
- **Integration**: **administrator** recurring reservation creation succeeds even when disabled.
- **Frontend**: admin panel renders, saves, and reloads the setting.
- **Frontend**: user panel hides or disables recurring reservation option when setting is disabled.
- **Frontend**: user panel shows recurring reservation option when setting is enabled.

## Out of scope

- Cancelling existing recurring reservations when the setting is disabled.
- Blocking administrator-created recurring reservations.
- Per-user or per-court recurring reservation permissions.
- Pricing, payments, analytics, or notifications.

## Dependencies

- EPIC-07 — Recurring Reservations.
- US-037 — Book a fixed weekly slot for a period I define.
- **Frontend: User settings endpoint** (to fetch complex configuration and render conditionally).

## Instructions for Devin

Implement the functionality that satisfies this user story for complex administrators and users.

**Key implementation points:**

1. **Backend:** In the recurring reservation creation handler, check if the user is an administrator. If yes, skip the setting validation. If no, check the `AllowUserRecurringReservations` setting.

2. **Backend:** The admin panel API endpoint for updating the setting should only be accessible to complex administrators.

3. **Frontend:** In the user booking panel, fetch the complex settings and conditionally render the recurring reservation option based on `allowUserRecurringReservations`. If disabled, hide the option or show it as disabled with a tooltip explanation.

4. **Frontend:** In the admin panel, display the setting as a toggle with clear labels explaining that this only affects regular users, not administrators.
