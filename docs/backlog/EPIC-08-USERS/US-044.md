# US-044 — Block a user

## Status

Ready

## Objective

As an administrator, I want to block a user so they cannot make new reservations.

## Functional description

This user story enables the administrator to block a user so that they cannot make new reservations. It belongs to EPIC-08 — User Management and Blocking.

## Acceptance criteria

- [ ] Block a user is implemented and available to the administrator.
- [ ] Blocks are scoped to a single complex.
- [ ] A blocked user cannot create reservations in the affected complex.
- [ ] Expired blocks are treated as lifted automatically.
- [ ] Blocks are scoped to a single complex; a user blocked in complex A can still use complex B.
- [ ] A blocked user cannot create reservations in the complex where they are blocked.
- [ ] Existing reservations are not automatically cancelled by a block (may be added later).
- [ ] Block records include user, complex, reason, blocked-by, blocked-at, and optional expiration.

## Business rules

- Search users of a complex.
- View user profile and reservation history.
- Block a user for a complex.
- Unblock a user.
- Optional expiration date for a block.
- Prevent blocked users from creating new reservations.
- Display block status to the affected user.
- A block in one complex does not affect the same user in another complex.

## Validations

- Validate required fields and data types server-side.
- Check for active blocks before allowing reservation creation.
- Return clear, structured error messages for invalid input.

## Error cases

- Invalid or missing input data.
- User is not authenticated or authorized.
- The referenced resource does not exist.

## Security considerations

- Authenticate and authorize every mutating request.
- Do not expose internal implementation details in error responses.
- Avoid logging sensitive data such as passwords, tokens, or PII.

## Technical notes

- `BlockedUser` entity: `Id`, `SportsComplexId`, `UserId`, `Reason`, `BlockedAt`, `BlockedUntil`, `BlockedByUserId`, `Status`.
- Validation must check active blocks before allowing a reservation to be created.
- A unique partial index or filter helps prevent duplicate active blocks per `(SportsComplexId, UserId)`.
