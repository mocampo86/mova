# US-043 — View a user's reservation history in my complex

## Status

Done

## Objective

As an administrator, I want to view a user's reservation history in my complex.

## Functional description

This user story enables the administrator to view a user's reservation history in my complex. It belongs to EPIC-08 — User Management and Blocking.

## Acceptance criteria

- [x] View a user's reservation history in my complex is implemented and available to the administrator.
- [x] Results are filtered and paginated when applicable.
- [x] Only active and public resources are returned to unauthorized callers.
- [x] Response times remain acceptable for mobile users.
- [x] Blocks are scoped to a single complex; a user blocked in complex A can still use complex B.
- [x] A blocked user cannot create reservations in the complex where they are blocked.
- [x] Block records include user, complex, reason, blocked-by, blocked-at, and optional expiration.

## Business rules

- Search users of a complex.
- View user profile and reservation history.
- Block a user for a complex.
- Unblock a user.
- Optional expiration date for a block.
- Prevent blocked users from creating new reservations.
- Display block status to the affected user.

## Validations

- Validate required fields and data types server-side.
- Validate query parameters and pagination inputs.
- Return clear, structured error messages for invalid input.

## Error cases

- Invalid or missing input data.
- User is not authenticated or authorized.

## Security considerations

- Authenticate and authorize every mutating request.
- Do not expose internal implementation details in error responses.
- Avoid logging sensitive data such as passwords, tokens, or PII.
- Ensure users can only view data they are allowed to access (multi-tenancy).
- Verify the actor belongs to or administers the affected complex.

## Technical notes

- `BlockedUser` entity: `Id`, `SportsComplexId`, `UserId`, `Reason`, `BlockedAt`, `BlockedUntil`, `BlockedByUserId`, `Status`.
- Validation must check active blocks before allowing a reservation to be created.
- A unique partial index or filter helps prevent duplicate active blocks per `(SportsComplexId, UserId)`.
