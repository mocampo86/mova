# US-052 — Access login and registration from the landing page

## Status

Ready

## Objective

As a visitor, I want to access login and registration from the landing page.

## Functional description

This user story enables the visitor to access login and registration from the landing page. It belongs to EPIC-09 — Landing Page and Public Site.

## Acceptance criteria

- [ ] Access login and registration from the landing page is implemented and available to the visitor.
- [ ] Google OpenID Connect authentication flow completes successfully.
- [ ] A valid JWT is issued after successful authentication.
- [ ] The JWT contains user id, email, name, and roles.
- [ ] The landing page loads quickly and is responsive on mobile.
- [ ] Login and admin access are visible and functional.

## Business rules

- Public home page.
- Explanation of how the platform works.
- Section for players (users).
- Section for owners (complexes).
- Featured complexes.
- User login / profile access.
- Admin access.
- Responsive and SEO-friendly design.

## Validations

- Validate required fields and data types server-side.
- Validate the Google token and map claims to local user data.
- Return clear, structured error messages for invalid input.

## Error cases

- Invalid or missing input data.
- User is not authenticated or authorized.
- The referenced resource does not exist.
- Google authentication fails or is cancelled.
- User does not exist locally and registration is required.

## Security considerations

- Authenticate and authorize every mutating request.
- Do not expose internal implementation details in error responses.
- Avoid logging sensitive data such as passwords, tokens, or PII.
- Store tokens securely; use `HttpOnly` cookies for refresh tokens.
- Validate JWT signature, issuer, and audience.

## Technical notes

- Use React Router for public routes.
- Lazy load below-the-fold content where beneficial.
- Implement a `PublicLayout` separate from `UserLayout` and `AdminLayout`.
- SEO can be static for the MVP; dynamic rendering is future work.

## Tests required

- **Unit**: domain logic and validation rules.
- **Integration**: API endpoint behavior and persistence.
- **E2E**: user flow through the frontend.

## Out of scope

- Features explicitly listed in later epics or future sprints.
- Advanced analytics, reporting, or notifications not required for the MVP.
- Future enhancements described in the epic technical notes.

## Dependencies

- EPIC-03 — Sports Complex Administration (for featured data).
