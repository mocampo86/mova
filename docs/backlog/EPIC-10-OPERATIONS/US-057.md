# US-057 — Operational runbooks for common procedures

## Status

Done

## Objective

As a team, I want operational runbooks for common procedures.

## Functional description

This user story provides the team with documented operational runbooks for the Mova platform. It belongs to EPIC-10 — Audit and Operations.

## Acceptance criteria

- [x] Operational runbooks for common procedures are documented and available to the team.
- [x] Health check, logging, correlation, error-rate, and alert procedures are documented.
- [x] Backup and restore procedures are documented.
- [x] Incident response, migration, rollback, and smoke-test procedures are documented.

## Business rules

- Runbooks are the authoritative source for operational procedures.
- Procedures must be safe to follow in local, QA, staging, and production environments.
- Secrets and connection strings must never be committed; use Key Vault, user secrets, or environment variables.
- Rollback procedures must protect data and preserve audit log integrity.

## Validations

- Verify the runbook references the correct health endpoints (`/health`, `/health/live`, `/health/ready`).
- Verify alert thresholds match the API configuration (`ErrorRateHealthCheck`, `ErrorRateTracker`, `RateLimiting`).
- Verify backup/restore commands are tested in a non-production environment monthly.
- Verify smoke tests validate the API health endpoints and, in staging, the error-rate readiness behavior.

## Error cases

- Missing or incorrect operational documentation.
- Backup/restore procedure fails in a drill.
- Health endpoint does not return the expected schema or status.
- Alert rule does not fire when the configured threshold is exceeded.

## Security considerations

- Do not expose connection strings, credentials, or internal endpoints in runbooks.
- Restrict alert receivers and action groups to authorized operators.
- Ensure deployment health probes do not expose internal details.

## Technical notes

- `AuditLog` entity: `Id`, `UserId`, `SportsComplexId`, `Action`, `EntityType`, `EntityId`, `CreatedAt`, `Metadata`.
- Use Serilog with correlation IDs propagated via `HttpContext`/`TraceIdentifier`.
- Application Insights for Azure; equivalent open-source alternatives for local/non-Azure environments.
- Rate limiting can be implemented with ASP.NET Core `RateLimiting` middleware.
- Keep audit logs immutable; do not update or delete audit records.
- Bicep monitoring templates are in `devops/azure` and the smoke test is in `devops/scripts/smoke-test.ps1`.

## Tests required

- **Unit**: not applicable for documentation.
- **Integration**: health endpoint behavior is covered by `Mova.IntegrationTests/Health/HealthCheckTests.cs`.
- **E2E/Smoke**: `devops/scripts/smoke-test.ps1` validates the health endpoints and can stress-test the error-rate readiness behavior in a DEBUG deployment.
